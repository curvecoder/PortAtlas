PortAtlas 5.0.0 names the files it writes by default after the product, records the executable path of services run under another account, and refuses inputs that 4.x skipped without a message. Several changes break existing setups: read the breaking changes below and the [upgrade guide](https://github.com/curvecoder/PortAtlas/blob/main/docs/how-to/upgrade-to-5.0.md) before deploying 5.0.0 to a service or a scheduled task.

## Breaking changes

- **Default file names start with `portatlas_`**: a file whose path is not set is written and read as `portatlas_audit.csv`, `portatlas_audit.ndjson`, `portatlas_topology.html` and `portatlas_dns_cache.json` instead of `netflow_*`. Without a configured path, `audit` starts a new log and an empty DNS cache. A `portatlas.json` that sets the paths keeps its files.
- **Map settings are checked in the configuration file**: an unknown value of `MapDirection`, `MapEdgeLabels`, `MapLayoutMode`, `MapSortMethod`, `MapRoutingMode`, `MapSpacingProfile`, `DrawioSubnets`, `DrawioEdgeMode` or `DrawioTheme` stops the command with exit code 1 and lists the accepted values, instead of falling back to the default. The spellings read by earlier versions are still accepted.
- **`--alias` pairs are checked**: a pair that cannot be read (`nas`, `=nas`, `192.168.1.5=`) is a command-line error naming the pair, with exit code 1, instead of being skipped. A pair is split at its first `=`, so an IPv6 alias (`fe80::10=nas.home.arpa`) is kept whole; `ip:host` is accepted for a four-part IPv4 address only.
- **`resolve` follows the name resolution keys**: `ResolveRemoteHostNames`, `ResolveIpOwners`, `DnsExcludedNetworks` and `CustomHostAliases` of the configuration file now apply to `resolve`. A `portatlas.json` copied from an isolated server with `"ResolveIpOwners": false` stops its RDAP queries.
- **Firewall matrices**: the rule and pair matrices of `export rules` are written in UTF-8 with a byte order mark, and replace the previous file only once complete. The `ExecutablePath` and `UserName` of a rule come from the most recently seen row, so the matrix no longer depends on the order of the logs given to `--input`.
- **Executable paths on Windows**: `ExecutablePath` is read without opening the process (ProcessForge 1.3.1), so it is now filled for services run under another account and for protected processes. A flow recorded by 4.x without a path starts a new row when 5.0.0 scans it with its path.

## Improvements

- **Dashboard**: the REMOTE cell has a second stop on the remote port; `Enter` or `X` there adds the port to `ExcludedRemotePorts`. The header shows the version of the executable instead of `v1.0.0`.

## Fixes

- **Dashboard**: excluding the REMOTE cell of a listening or UDP row wrote `0.0.0.0` (or `::`) to `ExcludedRemoteIps` and hid every listener; it is now refused with a warning. `L` and `A` no longer lower the view limit below the number of flows reloaded from the log.
- **Output that cannot be written**: an output file or folder that cannot be written (`map --html`, `export rules -o`, `export ndjson -o`) ends with one line naming the path and exit code 1, instead of a stack trace.
- **`map` and `export ndjson`** read each CSV log with the separator of its first line, as `export rules` and `resolve` already did, so logs from servers with different `CsvDelimiter` values are read together.
- **`export ndjson`** reads a `.ndjson` or `.jsonl` log as NDJSON instead of CSV, takes NDJSON logs from a folder, and never reads its own output.
- **`resolve`**: the rewritten log keeps the byte order mark of the original, and the first flow of a CSV log without header is resolved instead of being copied as a header.
- **`lookup`** applies `CustomHostAliases` and `DnsExcludedNetworks` as the audit does, instead of `ExcludedRemoteIps`.
- **`{Date}` and `{Timestamp}`** are written in the Gregorian calendar whatever the culture of the account.
- **`audit --no-dns`**: its help now says that it also turns RDAP owners and aliases off.
- **Graphical interface**: a profile or preferences file that cannot be read or written is reported in the profile bar instead of ending the command; the copy of the profiles to the per-user folder is completed before it is used, so an interrupted copy is made again at the next start.

## Packaging

The GUI archive no longer contains a `PortAtlas.runtimeconfig.json` without its executable. Extract the GUI archive into the folder of the command-line archive.

## Frameworks

ProcessForge 1.3.1 (was 1.3.0). Unchanged: SocketForge 2.1.1, FileForge.Core 1.4.1, TopologyForge 1.13.0.
