PortAtlas 6.3.0 can write the `export rules` matrices as Markdown, and the documentation now shows what each command writes on an example homelab. The audit log, the CSV matrices and the configuration keys do not change.

## New

- **Markdown matrices**: `export rules --format markdown` writes every matrix of the run as a Markdown file in place of the CSV file (`--format csv` stays the default). Each file starts with what one row stands for, a reminder that the matrix holds only the flows seen while the audit ran, the rule sets it serves (network and host firewalls, network security groups, OCI security lists) and a legend of its columns, then gives the rows as a table. The rows, their order and their values are those of the CSV matrix. Markdown syntax in a cell is escaped, so a host or process name shows as written. Without `-o`, the main matrix is named `portatlas_rules.md`. The graphical interface offers the option in the `export rules` form.

## Documentation

- **Example homelab**: `docs/examples/homelab/` holds three audit logs and a `portatlas.json` with address groups. The firewall rules guide, the CLI reference, the README and the tutorial quote the files that the commands write on this data set, option by option. The test suite runs each quoted command and fails when an example no longer matches what PortAtlas writes.
- The tutorial and the map rendering reference show the topology map of the homelab, in the layered layout and in the tree layout with bus routing.

## Frameworks

Unchanged: ProcessForge 1.3.1, SocketForge 2.1.1, FileForge.Core 1.4.1, TopologyForge 1.13.0.
