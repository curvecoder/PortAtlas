PortAtlas 6.0.0 turns `export rules` into a flow matrix tool: one pass now writes the flow, host rule and listening socket matrices beside the rule matrix, ready for a network team or for network security groups. The audit log, the DNS cache and the configuration keys do not change. Scripts that run `export rules`, or that run `map`, `export` or `resolve` without `-i`, may need changes: read [Upgrade from 5.x to 6.0](https://github.com/curvecoder/PortAtlas/blob/main/docs/how-to/upgrade-to-6.0.md) before deploying.

## New

- **`--flows-output`**: one row per flow, with the outbound rule of the source and the inbound rule of the destination merged. Each row gives the processes and observation counts of each end, and `SeenFrom` (`Source`, `Destination` or `Both`) tells which logs recorded the flow. An audited server's address is named after the server.
- **`--host-rules-output`**: for each flow, an outbound rule on the source and an inbound rule on the destination, as network security groups or security lists expect. Only hosts with a private address carry rules: a public address belongs to somebody else, and a loopback or unspecified address names no machine. `Audited` tells whether a log of the host was read, and `Evidence` whether the rule was `Observed` in the host's own log or `Inferred` from the peer's.
- **`--listeners-output`**: the listening sockets that `--listeners-only` would export, written in the same pass.
- The graphical interface offers the new options in its output section.

## Breaking changes

- **Default rule matrix name**: without `-o`, `export rules` writes `portatlas_rules.csv` instead of `firewall_rules.csv`.
- **Outputs that name an audit log**: an output option that named one of the logs to read replaced that log by a matrix without a message. The command now writes nothing, names the file and the option, and ends with exit code 1. Two output options naming the same file are refused the same way.
- **Pair matrix**: `--pairs-output` is built on the flow matrix. `FlowCount` counts flows, so a connection seen by both ends or a port shared by several processes is counted once; `ObservationCount` takes the larger count of the two ends of each flow; host names come from the flow matrix; a `SeenFrom` column, the list of the `SeenFrom` values of the pair's flows, is added at the end.
- **Loopback and unspecified destinations**: a loopback flow or a listener bound to `0.0.0.0` / `::` in the logs of two servers gave one rule, named after the server with the most recent observation. It now gives one rule per server.
- **`{Date}` and `{Timestamp}` in `OutputCsvPath`**: without `-i`, `map`, `export rules`, `export ndjson` and `resolve` (without `-i` or `--cache`) expanded the tokens at their own start: `{Date}` read only the log of the current UTC day, and `{Timestamp}` looked for a log no audit wrote, then stopped with `No audit log found for:`. They now stop at once with exit code 1 and a message that gives an `--input` pattern with `*` in place of the tokens.

## Fixes

- **`export ndjson`**: the output replaces the previous file only once complete. A log that could not be read, `Ctrl+C` or a full disk used to leave the previous export empty or truncated. A non-blank NDJSON line that is not valid JSON is now named: `Skipped <n> line(s) of <path> that are not valid JSON: lines <numbers>.`, with the first ten line numbers.

## Frameworks

Unchanged: ProcessForge 1.3.1, SocketForge 2.1.1, FileForge.Core 1.4.1, TopologyForge 1.13.0.
