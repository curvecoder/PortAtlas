PortAtlas 4.0.3 fixes crashes and a data loss found while reviewing 4.0.2. Commands, configuration files and outputs behave as in 4.0.2, except for the changes listed below.

## Fixes

- **NDJSON log erased**: `audit` resumes from its CSV log only, and it replaced the NDJSON log at start. An NDJSON log whose CSV log was missing or empty therefore lost all its flows. `audit` now stops before writing anything, with exit code 1 and a message naming both logs.
- **Invalid option value**: a value that is not a number for an integer option (`--interval abc`) is reported as a command-line error, with exit code 1, instead of an unhandled exception.
- **Port out of range**: `export rules` and `export ndjson` crashed on a log line whose port is outside 0-65535. The line is now left out, as `map` already did.
- **Intervals in the configuration file**: `ScanIntervalSeconds`, `LogRewriteIntervalMinutes` and `DnsResolutionTimeoutMs` below 1 are refused as an invalid configuration file, as the matching options already were. `ScanIntervalSeconds: 0` made `audit` crash after starting.
- **Locked file**: a file held by another program in a folder or a pattern given to `--input` crashed `export` and `map`. It is now left out and named on the console, and the other files are read. A file named directly that cannot be opened stops the command with `The audit log '<path>' cannot be read: …` and exit code 1.
- **Header read as a flow**: a CSV log whose header lacks the `ServerName` and `LocalPort` columns gave `export rules` a junk rule built from the header line. No flow is read from such a header any more.
- **NDJSON read as CSV**: a wildcard pattern such as `collected/*` brought NDJSON logs to `map` and `export ndjson`, which read them as CSV. A pattern now keeps the same extensions as a folder for the command (`.csv` for `map` and `export ndjson`; `.csv`, `.ndjson`, `.jsonl` for `export rules` and `resolve`). A pattern on another extension, such as `*.log`, no longer selects anything.
- **Failed periodic rewrite**: when `audit` could not replace its log at a periodic rewrite (file held by another program), nothing said so until the stop. The dashboard now shows a warning; the flows stay in memory and the next rewrite retries.
- **DNS cache after a cancelled start**: pressing `Ctrl+C` while `audit` was starting skipped saving the DNS cache. It is now saved on every way out.

## Frameworks

Unchanged: SocketForge 2.1.1, ProcessForge 1.3.0, FileForge.Core 1.4.1, TopologyForge 1.13.0.
