PortAtlas 3.7.0 makes `resolve` safe to run from several machines and lets it resolve a DNS cache on its own. The other commands, configuration files and outputs behave as in 3.6.0.

## New

- **Cache-only resolution**: `resolve --cache <file>` without `-i` leaves the audit logs alone and resolves the merged cache. Without `--force-resolve` only the entries without a name are resolved; with it, every entry is.
- **Resolution summary**: `resolve` reports how many entries were newly named, renamed, confirmed, kept after a failed lookup and left unresolved.

## Improvements

- **Entries without a name are retried**: a cache entry recorded without a host name is resolved again on the next run instead of staying unresolved for good.
- **No conflict with an unnamed entry**: when two caches disagree only because one entry has no name, the named entry is kept without a conflict warning.

## Fixes

- `resolve --force-resolve` no longer erases a resolved name from the master cache when a lookup finds nothing, for instance on a machine that cannot reach the internal DNS server.
- The master cache named by `--output-cache` is always merged before it is written, even when `--cache` does not list it. It was overwritten by the caches given on the command line.
