PortAtlas 4.0.0 rewrites the audit log from the flows held in memory, one up-to-date line per flow, and stops a command on a file or a value it cannot read instead of guessing or overwriting it. Several changes break existing setups: read the breaking changes below before updating a service or a scheduled task.

## Breaking changes

- **The audit log is rewritten, one line per flow**: `audit` loads the whole existing log at start, then rewrites the CSV log, and the NDJSON log given by `--ndjson`, at start, every `--rewrite-interval` minutes (`LogRewriteIntervalMinutes`, `5` by default) and at stop. Observation counts, last-seen dates and host names on disk are now current. A line break inside a field is written as a space. A rewrite interrupted by a power cut is completed at the next start from `<log>.pending`.
- **`--reload-history` and `ReloadHistoryLimit` are removed**: the whole log is always reloaded. A configuration file that still holds `ReloadHistoryLimit` is refused.
- **An audit log is resumed only if it holds the flow key**: `audit` stops with exit code 1 when the existing log lacks one of `FirstSeenUtc`, `Protocol`, `Direction`, `LocalPort`, `RemoteIp`, `RemotePort`, `ProcessName`, `ExecutablePath` and `TargetExecutable`, or holds a line it cannot read; the message names the columns or the line. `--columns` and `CsvColumns` without these columns are refused too. `ProcessName` is new in this list: it identifies a flow whose target and executable path are both empty. Existing logs written with the default columns need no change.
- **Flows launched by an interpreter get a new key**: the target of a script started by an interpreter is now read on Windows (SocketForge 2.0.0, ProcessForge 1.2.1). Such a flow is logged on a new line at the first run of 4.0.0; its old line, which has no target, stays in the log.
- **A DNS cache that cannot be read is refused**: `resolve` stops before any lookup when the cache named by `--output-cache` exists but cannot be read (truncated or invalid JSON, file held by another program or not readable by the account), and `audit` does the same for the cache named by `DnsCacheFilePath`. Both end with `The DNS cache '<path>' cannot be read: …` and exit code 1, and write nothing. Such a cache was read as empty, then replaced by the names of the current run.
- **The configuration file is checked**: an unknown key (keys are case-sensitive), a `null` value or a `null` list entry stops the command with exit code 1 and names the key. A configuration file that cannot be read or is not valid JSON stops the command instead of falling back to the defaults with a warning. A `--config` path that is empty or does not exist stops the command; without `--config`, a missing `portatlas.json` still gives the defaults.
- **Flow filters refuse what they cannot read**: a port or an address of `--include-ports`, `--exclude-ports`, `--include-ips` or `--exclude-ips` (or of `MapIncludedPorts`, `MapExcludedPorts`, `MapIncludedIps`, `MapExcludedIps`) that cannot be read stops `audit`, `map` and `export rules` with exit code 1, naming the option or key and the value. An IPv4 address must have four decimal bytes; a subnet with host bits set is read as its network. An IPv6 address in brackets (`[2001:db8::1]`, `[2001:db8::1]:443`) is refused, and ignored in the dashboard and DNS exclusions.
- **IPv6 rules no longer match IPv4 peers**: `::/0` matches IPv6 addresses only, and an IPv4-mapped rule with a prefix shorter than 96 (`::ffff:0:0/80`) is an IPv6 rule.
- **Audit logs are read as RFC 4180 CSV**: a command line spanning several lines is one flow. A quote never closed stops `audit`, `export` and `resolve` with exit code 1 and a message naming the log and the line where the field starts.
- **Firewall rule identifiers are `RULE-001`, `RULE-002`…** instead of `FLUX-…`. Rules are sorted on their whole group key, protocol and process included, so their numbers no longer depend on the order of the logs and may differ from 3.7.0.
- **Folders and patterns given to `--input` keep only audit logs**, one file per audit: the `_enriched` copy is preferred to its original, and a CSV log to the NDJSON log of the same name. `resolve` keeps both formats and skips an `_enriched` copy whose original is present. Skipped files are named on the console; a file given by its path is always read. Counts may change for folders that held copies.
- **Output formats**: the NDJSON audit log is written in UTF-8 without a byte order mark (the CSV log keeps it). In the rule and pair matrices of `export rules`, a value starting with `=`, `+`, `-`, `@`, a tab or a carriage return is prefixed with an apostrophe so that a spreadsheet does not run it as a formula. With `--listeners-only`, a `Listen` line whose direction is not `Listening` is no longer exported, and bound UDP sockets are kept.

## Improvements

- **Stop through the standard input**: when `PORTATLAS_STOP_ON_INPUT_END` is `1` and the standard input is redirected, closing that input stops a command as `Ctrl+C` does: `audit` writes its logs and saves its DNS cache, `resolve` saves the addresses already resolved and ends with exit code `130`, and the other commands end at once with `130`. The graphical interface uses it: Stop, or closing the main window during a run, lets the command save its work, and the process tree is killed only if it is still running after 10 seconds. Without the variable the input is not read, so a service started with an empty input keeps running.
- **`resolve` stops on `Ctrl+C`** (and `SIGTERM` on Linux and macOS): the addresses resolved before the stop are saved to the cache named by `--output-cache`, and the command ends with exit code `130`.
- **Failed socket scans**: a scan that fails is reported on the dashboard banner, or on a timestamped line without the dashboard, and the next scan runs. After 10 failed scans in a row, `audit` writes its logs and ends with exit code 1.
- **Host address**: the address shown for the host is the first IPv4 address of an active interface with an IPv4 gateway, and the interfaces are read again every minute.
- **Lookups without an answer are retried**: in `audit`, an owner lookup (RDAP) that gets no answer is not cached as "no owner" and is asked again after 15 minutes. In `resolve`, a DNS timeout or an RDAP server that does not answer no longer writes a `None` entry; the previous entry is kept.
- **`map` names the lines it leaves out**: for each log, the numbers of the lines without a valid local or remote port (the first ten, then "and N more"). These lines were mapped with port 0.
- **Recognising a large file**: at most about one million characters are read to tell whether a file is an audit log, so a large file without line breaks is no longer loaded whole.

## Fixes

- `audit`: flows reloaded at start get the host name already in the DNS cache; an observation made while a host name is written is no longer lost; a reloaded flow is no longer tracked twice, and the raw lines of the log no longer stay in memory.
- `audit`: the HTML map is generated one at a time; a map file that is locked or read-only shows a warning on the dashboard; a failed map write from the `M` key no longer stops the `Q` key from working.
- `audit`: an exclusion added from the dashboard writes only the missing entries to the configuration file, leaves the other keys as written, and the banner says when it could not be saved.
- `audit`: `CustomHostAliases` and `DnsExcludedNetworks` are no longer stored in the DNS cache, so removing an alias or an exclusion from the configuration takes effect; such entries left by an older version are ignored.
- The configuration file, the DNS cache, the profiles of the graphical interface and the files written by `resolve` are replaced whole, so that a crash during a write no longer leaves a truncated file.
- One badly typed entry of a DNS cache is skipped instead of emptying the whole cache; an RDAP answer of an unexpected shape no longer stops the lookup.
- `export rules`: each CSV log is read with the separator found on its first line (`CsvDelimiter` only breaks a tie), so a log written with `;` no longer gives an empty matrix. Address filters test both ends of a rule, and a listener is tested on its bound address. Host filters test the consolidated rule, by name and address. Server and remote names come from the most recent line that has one.
- `resolve`: audit logs written with a tab or `|` separator are resolved and enriched; an NDJSON line without `remoteHostName` no longer stops the run; the merged output cache is no longer counted in "Source caches processed"; a cache listed in `--cache` that the account cannot read adds no names instead of stopping the run with a stack trace.
- `lookup`: a DNS cache that cannot be read (truncated or invalid JSON, file held by another program or not readable by the account) is reported as a cache error naming the file, instead of "Entry not present in file".
