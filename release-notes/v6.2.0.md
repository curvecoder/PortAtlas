PortAtlas 6.2.0 lets `CustomHostAliases` name a whole subnet and adds a firewall rule matrix grouped by address group to `export rules`. It also fixes two DNS cache and time format issues. The audit log and the existing matrices do not change.

## New

- **Subnets in `CustomHostAliases`**: a key can now be a CIDR subnet (`"192.168.10.0/24": "lab"`) as well as an address. An address takes the name of its most precise range, so `192.168.10.20` keeps its own alias inside an aliased `/24`. `audit --alias` accepts `range=host` the same way. A file key and an `--alias` value that designate the same range, even written differently, give the value of the option. `lookup` names the subnet the alias came from.
- **Group rule matrix**: `export rules --group-rules-output <path>` writes one row per source group, destination group, protocol and port. The groups come from the new `AddressGroups` key (`{ "lab": ["192.168.10.0/24"] }`) and from `--address-group name=range`, which adds to the file. An address belongs to the group of its most precise range. An address in no group stands for itself, and the source of a listening socket is `Any`.
  - The command stops with exit code 1 before reading any log in three cases: a range given to two groups, a range that cannot be read, or a group named `Any` or named as an address.
  - Without `--group-rules-output` the groups are not built, and `--address-group` writes a warning.
  - The other matrices keep one row per address.
  - The graphical interface offers both options in the `export rules` form.

## Changes

- **Alias keys are read as addresses or subnets**: earlier versions accepted a shortened IPv4 key (`"10"`, read as `0.0.0.10`) or an IPv6 address in brackets (`"[fe80::1]"`). These keys are now ignored. Write the full address (`"10.0.0.10"`, `"fe80::1"`). `--alias` refuses such values with an error that names them.

## Fixes

- **DNS cache in a read-only folder**: when the account could not write to the cache folder, the delayed save ended on an unobserved exception and the final save threw. Both are now tolerated, and the file keeps its previous version. `resolve` no longer reports a saved cache when the write failed.
- **`lookup` resolution time**: the `Resolved at (UTC)` line used the time separator of the current culture. It is now always written as `HH:mm:ss`, like the dashboard times since 6.1.0.

## Frameworks

Unchanged: ProcessForge 1.3.1, SocketForge 2.1.1, FileForge.Core 1.4.1, TopologyForge 1.13.0.
